## 关键决策和限制

- 缓存端口位于 Service 与 Redis 适配器之间；Repository 仍只表示 MySQL 持久化契约，MySQL 是事实来源。
- 文档值使用 String/JSON，而不是把领域对象字段拆成 Hash；当前读取总是整体返回文档，JSON 更适合版本化和一次往返。
- Key 包含 `v1`，为将来不兼容的值结构变化保留隔离边界；禁止通过 `FLUSHALL` 处理版本升级。
- 文档详情使用 10～12 分钟 TTL，随机抖动用于分散集中回源；分页组合多、失效范围大且复用率不确定，暂不缓存。
- 第 2 天只完成正值路径。空值缓存、Redis 连接/超时降级、损坏 JSON 回退、命中率和绕过计数仍属于第 3 天；在这些行为完成前，缓存开启且 Redis 故障时不能宣称核心查询已具备降级能力。
- 当前修改均留在工作区；未经用户明确授权不得提交或推送。
- 后续测试 profile 的 HTTP 验收固定使用 `spring-boot:test-run`；不得再次尝试用 `spring-boot:run + useTestClasspath=true` 加载测试配置。只有明确需要普通 `run` 时才显式加入 `target/test-classes`。
