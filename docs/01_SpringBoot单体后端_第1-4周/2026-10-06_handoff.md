### 工单模型与状态流转

- 新增 `Ticket` 模型，包含 `id`、`title`、`description` 和 `status`。
- 新增工单状态枚举：`PENDING`、`PROCESSING`、`RESOLVED`、`CLOSED`。
- 状态只允许按照 `PENDING → PROCESSING → RESOLVED → CLOSED` 顺序流转。
- 跳级、回退和重复设置同一状态均返回 HTTP 400 和错误码 `INVALID_STATUS_TRANSITION`。
- 新增 `TicketRepository` 接口及基于 `ConcurrentHashMap` 的内存实现。
- 新增 `TicketService` 和 `TicketController`，保持 Controller → Service → Repository 分层。

### 工单接口与验证

- `POST /tickets`：创建工单，初始状态固定为 `PENDING`，成功返回 HTTP 201。
- `GET /tickets/{id}`：按 ID 查询工单，成功返回 HTTP 200。
- `PUT /tickets/{id}/status`：更新到下一个合法状态，成功返回 HTTP 200。
- 工单不存在时返回 HTTP 404 和错误码 `RESOURCE_NOT_FOUND`。
- 状态缺失时返回 `VALIDATION_ERROR`；无法识别的状态值返回 `INVALID_REQUEST_BODY`。
- 新增 9 个 `TicketService` 测试和 10 个工单接口集成测试。
- 按 TDD 顺序分别确认创建接口、状态机和状态更新接口测试先失败，再实现最小代码使其通过。
- 在独立的 18080 端口实际启动应用，验证创建工单、合法更新到 `PROCESSING`，以及非法跳级返回 HTTP 400；验证后已停止临时服务。
