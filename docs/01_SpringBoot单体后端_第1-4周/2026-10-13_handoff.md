- `cleanup.sql` 已在第 1 天包含 `DELETE FROM documents`，第 3 天直接复用，不为制造差异重复修改。
- 用户和文档的 MyBatis 适配器目前只有少量相似转换代码，尚未形成值得通用基类的重复，本日不提前抽象。
- 首次运行验证失败，原因是 `spring-boot:run` 默认类路径不含 `src/test/resources/application-test.properties`；本次通过 `--spring.config.additional-location=file:src/test/resources/` 显式加载测试配置，未复制或输出数据库密码。
- Mockito/Byte Buddy 动态 Java Agent 警告仍然存在，属现有测试依赖行为，本日不扩展处理。
- Git 实际状态已覆盖旧交接描述：第 4 天代码已提交并推送，`HEAD` 与 `origin/codex/feat-mysql-mybatis` 均为 `51ebce7`；当前只有本轮自测题库和交接文档变更尚未提交。
- 当前目录是普通 Git 检出，不是关联 worktree；用户明确指定继续当前开发分支，因此原地实施，不额外创建分支或 worktree。
- 行锁实测证明 `FOR UPDATE` 必须覆盖读取、校验和更新的完整事务；只按主键锁一条工单可以缩小锁范围并降低无关阻塞与死锁风险。
- 并发测试使用测试专用 Repository 装饰器：无锁路径在普通读取后同步两个线程，确保两者都读到旧状态；加锁路径在读取前同步，再由真实 MySQL 决定锁等待。装饰器不替换 Mapper 或数据库行为。
- 工单插入 SQL 固定写入 `PENDING`，调用方不能指定初始状态；数据库默认值和 CHECK 约束继续作为数据边界保护。
- `TicketService.updateStatus` 是由 Controller 或测试通过 Spring Bean 调用的 public 方法，不存在类内自调用绕过事务代理的路径。
- 独立审查将“工单输入长度未覆盖数据库限制”评为 Important；已增加标题 200 字符上限和描述 65,535 UTF-8 字节上限，并通过 RED→GREEN 与完整回归修复。
- 描述长度使用自定义 Jakarta Validation 约束按 UTF-8 实际字节数计算，避免把 MySQL `TEXT` 的字节上限错误当作 Java 字符数。
- 审查提出一项非阻塞 Minor：当前并发测试能确定性复现旧普通读取路径，但若未来只删除事务或 SQL 行锁，失锁回归能否稳定失败仍部分依赖调度；本次不扩展测试基础设施，留待后续稳定性测试评估。
