## 已完成功能

- 新增统一 `PageRequest`，页码从 1 开始、每页 1～100 条，offset 使用 `long` 计算；非法分页参数映射为 HTTP 400、`VALIDATION_ERROR`。
- 新增 `PageResult<T>`、`PageResponse<T>`、文档/工单分页查询对象、摘要模型和摘要响应 DTO。
- 新增 `GET /documents?titlePrefix=&page=1&size=20`，支持标题前缀筛选。
- 新增 `GET /tickets?status=&keyword=&page=1&size=20`，支持状态、标题关键字和组合筛选。
- 两个列表固定按 `created_at DESC, id DESC` 排序，items 与 count 使用相同筛选条件并排除 `deleted = 1`。
- Mapper 列表 SQL 只选择摘要字段，不读取文档 `content` 或工单 `description`；HTTP 响应也不包含大文本。
- Service 负责空白筛选归一化、页码到 offset 的转换和领域摘要到响应 DTO 的映射；Controller 不访问 Repository。
- 非法工单状态查询参数返回 HTTP 400、`INVALID_REQUEST_PARAMETER`；JSON 请求体中的非法枚举仍保持 `INVALID_REQUEST_BODY`。
- MyBatis Repository 使用显式 `ESCAPE '='`，把 `%`、`_`、`=` 按普通文本处理，避免真实数据库与内存测试替身的筛选语义不一致。
- 内存 Repository 保存创建时间，并实现与 MyBatis 相同的筛选、分页和稳定排序语义，继续只用于轻量 Service 测试。
- README 已更新为 MySQL/MyBatis 现状，补充两个分页接口、启动配置、错误码和当前限制。
- [第二周第 1～6 天自测题与参考答案](第二周_第1-6天自测题与参考答案.md)已统一收录第 5 天的分页、索引、执行计划题目和第 6 天的集成验证、配置安全、错误契约题目。

- 新增 `src/test/resources/db/explain-fixtures.sql`，在 `intern_project_test` 生成 1,200 条文档、1,200 条工单和 100 条角色权限关联。
- 脚本不包含凭据；所有写语句都受 `DATABASE() = 'intern_project_test'` 条件保护，并按外键依赖顺序清理 `role_permissions`、`user_roles`、父表和业务表。
- 工单带 `status='PROCESSING'` 的分页查询使用 `idx_tickets_status_deleted_created_id`，传统计划估算 288 行；实际索引节点输出 20 行、`loops=1`，没有额外排序节点。
- 工单不带状态条件时使用 `idx_tickets_deleted_created_id`，传统计划估算 1,152 行，同样按索引顺序直接取得前 20 行。
- 文档 `LIKE 'Spring%'` 使用 `idx_documents_deleted_title_id` 的范围扫描，估算并实际输出 180 个候选，再做 `created_at DESC, id DESC` 排序。
- 文档 `LIKE '%Spring%'` 只能有效利用 `deleted` 前导列，传统计划估算检查 1,140 条有效数据，并出现额外排序。
- 角色权限查询使用联合主键 `PRIMARY(role_id, permission_id)`，传统计划显示 `Using index`，分析计划明确显示 `Covering index lookup`，实际输出 100 行、`loops=1`。
- 完整 SQL、key、估算 rows、actual rows、loops、actual time 和结论已写入[第二周 MySQL 与 MyBatis 练习记录](第二周_MySQL与MyBatis练习记录.md)；没有把单次耗时转写为性能提升百分比。
