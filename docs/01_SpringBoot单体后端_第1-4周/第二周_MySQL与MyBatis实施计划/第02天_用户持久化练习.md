# 第 02 天：用户持久化练习实施计划

> **供执行者使用：** 实施本计划前必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，并使用复选框（`- [ ]`）逐项跟踪。

**目标：** 由用户主导完成第一个 MyBatis 纵向切片，使用户创建和按 ID 查询真实写入 MySQL，并稳定处理唯一约束冲突和逻辑删除。

**架构：** `UserService` 继续依赖 `UserRepository`；新增 `MyBatisUserRepository → UserMapper → UserMapper.xml`。Mapper 使用数据库 Record，Repository 负责映射为现有不可变 `User`，Controller 和响应 JSON 不感知持久化变化。

**技术栈：** Java 21、Spring Boot 4.1.1、MyBatis 4.0.0、MySQL 8.4、JUnit 5、AssertJ、MockMvc。

**设计规格：** `docs/01_SpringBoot单体后端_第1-4周/2026-10-06_MySQL与MyBatis持久化设计.md`

## 全局约束

- 这是用户主导练习：先提供测试目标、签名和提示，用户提交尝试后优先代码审查，不直接替用户写完整实现。
- `UserRepository` 的现有 `save(String, String)`、`findById(Long)` 对 Service 保持兼容。
- `InMemoryUserRepository` 保留给单元测试，但移除运行时 `@Repository` Bean 身份。
- Mapper 参数必须使用 `#{}`；禁止 `${}` 拼接用户名、邮箱或 ID。
- 重复用户名或邮箱返回 HTTP 409、错误码 `DUPLICATE_RESOURCE`、消息“用户名或邮箱已存在”。

## 审查重点

- 自增主键是否回填到 Record 并返回给 API。
- 逻辑删除用户是否被 `findById` 排除。
- 重复约束是否由数据库兜底而非仅依赖先查后插。
- MySQL 异常是否被翻译为稳定领域异常，响应不泄露 SQL。
- 用户代码是否绕过 Repository 让 Service 直接依赖 Mapper。

**接口：**

- 产出：保存、主键回填、查询、重复冲突、逻辑删除与删除后身份不可复用六个行为契约。

- [x] **步骤 1： 用户编写集成测试骨架**

使用 `@SpringBootTest`、`@ActiveProfiles("test")`、测试前执行 `classpath:db/cleanup.sql`。测试方法和断言：

- `savesUserWithGeneratedId()`：返回 ID 为正数，用户名和邮箱不变。
- `findsActiveUserById()`：保存后查询得到相同字段。
- `doesNotFindLogicallyDeletedUser()`：用 `JdbcTemplate` 将 `deleted` 更新为 1，Repository 返回 empty。
- `rejectsDuplicateUsername()`：第二次保存抛 `DuplicateResourceException`，消息为“用户名或邮箱已存在”。
- `rejectsDuplicateEmail()`：同上。
- `doesNotReuseDeletedIdentity()`：逻辑删除后再次保存相同用户名或邮箱，仍由唯一约束拒绝。

### 任务 2： 实现最小 User Mapper 与 Repository 适配器

**文件：**
- 新建： `src/main/java/com/xcy/internproject/repository/mybatis/record/UserRecord.java`
- 新建： `src/main/java/com/xcy/internproject/repository/mybatis/mapper/UserMapper.java`
- 新建： `src/main/resources/mapper/UserMapper.xml`
- 新建： `src/main/java/com/xcy/internproject/repository/mybatis/MyBatisUserRepository.java`
- 新建： `src/main/java/com/xcy/internproject/exception/DuplicateResourceException.java`
- 修改： `src/main/java/com/xcy/internproject/repository/InMemoryUserRepository.java`
- 修改： `src/main/java/com/xcy/internproject/exception/GlobalExceptionHandler.java`

**接口：**
- 依赖： `users(id, username, email, deleted)`。
- 产出：
  - `int UserMapper.insert(UserRecord record)`，通过 `useGeneratedKeys` 写回 `record.id`。
  - `UserRecord UserMapper.findById(Long id)`，SQL 固定包含 `deleted = 0`。
  - `MyBatisUserRepository implements UserRepository`。
  - `DuplicateResourceException(String message)`。

- [x] **步骤 1： 用户实现 `UserRecord`**

字段固定为 `Long id`、`String username`、`String email`，提供 MyBatis 所需的无参构造、getter 和 setter；不包含业务方法。

- [x] **步骤 2： 用户定义 Mapper 接口和 XML**

插入 SQL 只写 `username`、`email`，主键由数据库生成；查询 SQL 按 `id` 且 `deleted = 0`。XML namespace 和方法 ID 必须与接口完全一致。

- [x] **步骤 3： 用户实现 Repository 适配器**

构造器注入 `UserMapper`。`save` 创建 Record、插入并映射为 `User`；`findById` 将可空 Record 转为 `Optional<User>`。

- [x] **步骤 4： 隐藏数据库唯一约束异常**

在适配器保存边界捕获 Spring `DuplicateKeyException`，转换为 `DuplicateResourceException("用户名或邮箱已存在")`。不要解析并返回原始 SQL 消息。

- [x] **步骤 5： 切换运行时 Bean**

给 MyBatis 适配器添加 `@Repository`，从 `InMemoryUserRepository` 移除 `@Repository` 导入和注解。保留其公共构造与方法，确保 Service 单元测试可直接 `new`。

- [x] **步骤 6： 增加全局异常映射**

`GlobalExceptionHandler` 新增处理器：HTTP 409，`ApiResponse.error("DUPLICATE_RESOURCE", exception.getMessage())`。

- [x] **步骤 7： 运行 Repository 测试确认 GREEN**

执行： `mvn -Dtest=MyBatisUserRepositoryIntegrationTest test`

预期： 6 个测试通过。
