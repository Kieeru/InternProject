# 第 06 天：集成验证与文档实施计划

> **供执行者使用：** 实施本计划前必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，并使用复选框（`- [ ]`）逐项跟踪。

**目标：** 用完整自动化测试、真实启动、HTTP 调用和应用重启证明第二周持久化成果，并把可复现步骤和真实证据写入 README 与 handoff。

**架构：** 不再增加业务功能；本日只修复验收暴露的问题、统一配置与文档、检查安全和仓库状态。任何行为缺陷都先补回归测试再修复。

**技术栈：** Maven、Spring Boot、MySQL 8.4、PowerShell、MockMvc、JUnit 5、Git 只读检查。

**设计规格：** `docs/01_SpringBoot单体后端_第1-4周/2026-10-06_MySQL与MyBatis持久化设计.md`

## 全局约束

- 不新增认证、Redis、Docker、MinIO、Kafka、微服务或其他第三周以后功能。
- 只有最新命令实际成功后才能记录“通过”；不得沿用第一周 40 个测试的历史数字。
- 运行验证必须包含停止并重新启动应用后的持久化查询。
- README 和 handoff 不写密码、个人路径或虚假性能数字。
- 未经用户明确授权不提交、不推送、不创建分支。

## 审查重点

- 测试是否依赖执行顺序、旧数据库残留或开发库数据。
- 应用重启后 ID 和内容是否仍可查询。
- 错误响应是否泄露 SQL、JDBC URL、用户名、堆栈或内部异常类型。
- README 的命令、profile、环境变量和接口示例是否与代码一致。
- Git 是否误包含 `.env`、本地配置、数据库导出、日志、IDE 文件或 `target/`。

### 任务 1： 完整自动化验证与失败修复

**文件：**
- Modify only if a failing regression test proves a defect: affected production and test files。

**接口：**
- 依赖： 第 01～05 天的全部代码与测试。
- 产出： 最新、可重复的 Maven 全套测试结果。

- [ ] **步骤 1： 确认环境和目标数据库**

执行： `Get-Service MySQL`

预期： `Status` 为 `Running`。

执行： `mysql -u <测试用户名> -p -D intern_project_test -e "SELECT DATABASE();"`

预期： 只返回 `intern_project_test`。

- [ ] **步骤 2： 从干净测试数据运行完整套件**

执行： `mvn test`

预期： BUILD SUCCESS，0 failures、0 errors；记录实际 Tests run 总数和警告。

- [ ] **步骤 3： 如有失败，按缺陷流程处理**

定位最小失败测试；若缺少回归覆盖，先写能够稳定复现的失败测试，再做最小修复。每次修复先运行目标测试，再重新运行 `mvn test`。

- [ ] **步骤 4： 检查测试隔离**

连续执行两次 `mvn test`。两次都必须通过，以排除唯一约束冲突、未清理数据和执行顺序依赖。

### 任务 2： 实际启动、重启和 HTTP 全链路验证

**文件：**
- No planned source changes；发现缺陷时按 Task 1 的回归流程修改。

**接口：**
- 依赖： `local` profile 和开发库 `intern_project`。
- 产出： 创建、重启后查询、分页、合法与非法状态流转的运行证据。

- [ ] **步骤 1： 初始化开发库并启动应用**

人工确认目标库为 `intern_project`，执行 `schema.sql`；设置 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 环境变量后启动：

执行： `mvn spring-boot:run "-Dspring-boot.run.profiles=local"`

预期： Tomcat 启动成功，无 DataSource 或 Mapper 错误。

- [ ] **步骤 2： 创建三类资源并保存返回 ID**

使用 PowerShell `Invoke-RestMethod` 或 Apifox 调用用户、文档、工单创建接口。断言 HTTP 201、`code=OK`，记录三个 ID，不记录凭据。

- [ ] **步骤 3： 停止并重新启动应用**

正常停止 Spring Boot 进程，再使用相同 profile 启动。不得重新初始化或清空开发库。

- [ ] **步骤 4： 验证重启后持久化**

按此前 ID 调用三个 GET 详情接口，断言 HTTP 200、字段与创建时一致。

- [ ] **步骤 5： 验证分页和状态流转**

调用两个列表接口，确认新资源出现且不包含大文本；将工单合法更新到 `PROCESSING`，再尝试重复设置 `PROCESSING`，确认后者 HTTP 400、`INVALID_STATUS_TRANSITION`。

- [ ] **步骤 6： 验证典型失败响应不泄露内部信息**

调用不存在 ID、无效分页、无效工单状态查询参数和重复用户；响应不得包含 SQL、表名、约束名、JDBC URL、Java 异常类或堆栈。

- [ ] **步骤 7： 停止验证服务**

确认临时 Spring Boot 进程已正常停止，不遗留占用 8080 端口的 Java 进程。
