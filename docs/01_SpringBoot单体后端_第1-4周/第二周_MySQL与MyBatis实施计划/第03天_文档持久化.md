# 第 03 天：文档持久化实施计划

> **供执行者使用：** 实施本计划前必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，并使用复选框（`- [ ]`）逐项跟踪。

**目标：** 复用用户模块已验证的模式，把文档创建和按 ID 查询迁移到 MySQL，同时保持现有 HTTP 响应完全兼容。

**架构：** 新增 `MyBatisDocumentRepository → DocumentMapper → DocumentMapper.xml`，使用数据库 Record 隔离审计字段。Repository 只向 Service 返回现有 `Document`；正文继续存入 `LONGTEXT`，不提前引入文件上传、MinIO 或版本模型。

**技术栈：** Java 21、Spring Boot 4.1.1、MyBatis 4.0.0、MySQL 8.4、JUnit 5、AssertJ、MockMvc。

**设计规格：** `docs/01_SpringBoot单体后端_第1-4周/2026-10-06_MySQL与MyBatis持久化设计.md`

## 全局约束

- 保留 `DocumentRepository.save(String, String)` 与 `findById(Long)` 的 Service 契约。
- 现有 `POST /documents` 和 `GET /documents/{id}` 的状态码、JSON 字段和中文消息不得变化。
- `content` 使用 `LONGTEXT`，不增加对象存储地址、版本、权限或创建人。
- `InMemoryDocumentRepository` 保留给单元测试，但不再注册为运行时 Bean。
- 正常查询固定过滤 `deleted = 0`。

## 审查重点

- 长正文是否完整往返，不发生截断或字符集错误。
- 标题 200 字符边界是否与 DTO 和数据库一致。
- 逻辑删除文档是否按不存在处理。
- Mapper Record 中的审计字段是否意外出现在现有详情 JSON。
- Controller 集成测试是否真实使用 MySQL 而非残留内存 Bean。
