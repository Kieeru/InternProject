# 第 01 天：数据库基础实施计划

> **供执行者使用：** 实施本计划前必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，并使用复选框（`- [ ]`）逐项跟踪。

**目标：** 建立可重复初始化的 MySQL 开发/测试环境、项目依赖与数据库结构验证，为后续 Repository 迁移提供稳定基础。

**架构：** 应用和测试连接不同数据库；`schema.sql` 是单一 DDL 来源，测试 profile 自动初始化结构但不自动注入业务数据。现有内存 Repository 暂时继续提供运行时 Bean，使本日只验证基础设施，不混入业务迁移。

**技术栈：** Java 21、Spring Boot 4.1.1、MyBatis Starter 4.0.0、MySQL 8.4、JUnit 5、Spring JDBC Test。

**设计规格：** `docs/01_SpringBoot单体后端_第1-4周/2026-10-06_MySQL与MyBatis持久化设计.md`

## 全局约束

- 只新增 MyBatis 4.0.0 Starter 与 MySQL JDBC 驱动；不引入 H2、Flyway、MyBatis-Plus 或 Testcontainers。
- 开发库名固定为 `intern_project`，测试库名固定为 `intern_project_test`。
- 密码不进入仓库；测试失败时不得回退内存数据库或 H2。
- 所有表使用 InnoDB、`utf8mb4`、`BIGINT` 主键、`DATETIME(6)` 审计时间和明确约束。
- 本日不迁移任何业务 Repository，不改变现有 HTTP 行为。

## 审查重点

- 连接串误指向开发库时，清理脚本是否可能破坏开发数据。
- 测试库不存在、密码缺失或 MySQL 停止时，错误是否明确。
- `schema.sql` 重复执行是否成功，外键创建顺序是否正确。
- 用户名/邮箱唯一约束和工单状态 CHECK 是否真实存在。
- 测试 profile 是否会意外写入生产配置或日志输出密码。
