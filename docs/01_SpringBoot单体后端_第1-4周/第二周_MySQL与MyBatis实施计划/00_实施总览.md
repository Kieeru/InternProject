# 第二周 MySQL 与 MyBatis 持久化实施计划总览

> **供执行者使用：** 实施本计划前必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，并使用复选框（`- [ ]`）逐项跟踪。

**目标：** 在不改变现有七个 HTTP 接口行为的前提下，用 MySQL 8.4 和原生 MyBatis 持久化用户、文档与工单，增加列表分页、索引验证和并发安全的工单状态流转。

**架构：** 保留 Controller → Service → Repository 分层，在 Repository 接口后增加 MyBatis 适配器、Mapper 接口和 XML SQL。Service 继续承载业务规则与事务边界，真实 MySQL 用于 Repository、HTTP 和并发集成测试，内存 Repository 仅保留给快速 Service 单元测试。

**技术栈：** Java 21、Spring Boot 4.1.1、Maven、MyBatis Spring Boot Starter 4.0.0、MySQL 8.4 LTS、JUnit 5、AssertJ、MockMvc。

**设计规格：** `docs/01_SpringBoot单体后端_第1-4周/2026-10-06_MySQL与MyBatis持久化设计.md`

## 全局约束

- Java 固定为 21，Spring Boot 固定为 4.1.1；未经用户同意不降级或切换大版本。
- 只引入 `org.mybatis.spring.boot:mybatis-spring-boot-starter:4.0.0` 和 MySQL JDBC 驱动，不引入 MyBatis-Plus、JPA、Flyway、H2 或 Testcontainers。
- 所有外部输入仍通过 DTO 和 Jakarta Validation 或稳定的业务校验处理；面向用户的消息必须为中文。
- 现有 `POST/GET /users`、`POST/GET /documents`、`POST/GET /tickets`、`PUT /tickets/{id}/status` 的路径、状态码、响应结构和错误码不得回退。
- 数据库密码只允许来自环境变量或已忽略的本地配置文件，不得写入 Git、日志、README 或测试输出。
- 生产代码必须按 TDD 顺序修改；每个任务先确认测试因预期行为缺失而失败，再实现最小代码。
- 用户主导的练习先给接口、测试目标和提示；除非用户明确要求，不直接替用户写完第 02 天核心实现。
- `mvn test` 在最终完成前必须连接独立的 `intern_project_test` 数据库并全部通过；不得静默回退到内存实现。
- Git 提交、推送和建分支只有在用户明确授权后执行；计划中的提交点仅给出建议提交信息。
- 计划文档的文件名、标题、栏目和说明统一使用中文；Java 类名、源码文件名、配置键、API、命令及 MySQL/MyBatis 等技术标识保留其工程名称，不翻译为中文标识符。

## 审查重点

1. 重复用户名或邮箱：数据库唯一约束必须兜底，API 返回 HTTP 409、`DUPLICATE_RESOURCE` 和中文消息，不能泄露 SQL 或约束名；由第 02 天测试锁定。
2. 逻辑删除记录：按 ID 查询返回 404，列表不出现，唯一身份字段仍不可复用；由第 02～05 天测试锁定。
3. 分页边界：`page < 1`、`size < 1`、`size > 100` 返回 HTTP 400 和稳定中文消息，空白筛选条件按未提供处理；由第 05 天测试锁定。
4. 并发状态更新：两个并发的 `PENDING → PROCESSING` 只有一个成功，另一个返回 `INVALID_STATUS_TRANSITION`；由第 04 天真实 MySQL 测试锁定。
5. 数据库不可用或配置缺失：测试与应用必须快速、明确失败，不得切换内存存储制造假通过；由第 01 天配置验证和第 06 天运行验证锁定。

## 统一执行规则

1. 开始每日任务前执行 `git status --short --branch`，保护已有修改。
2. 阅读本总览、当日计划、设计规格和最新 handoff。
3. 只运行当日指定的目标测试确认 RED；不要用编译错误冒充业务测试失败。
4. 实现最小生产变更，运行目标测试确认 GREEN，再允许重构。
5. 每个任务结束运行受影响模块测试；每日结束运行 `mvn test`。
6. 需要数据库的命令先确认 `Get-Service MySQL` 为 `Running`，并确认连接的是 `intern_project_test`，不得对其他数据库执行清理脚本。
7. 每个提交点先检查 `git diff --check` 与 `git status`；未经用户授权只报告建议提交信息，不执行提交。
8. 真实进度、测试数量、执行计划和阻塞写入当天 `YYYY-MM-DD_handoff.md`，计划文件本身不当作完成记录。

## 完成定义

- 七个既有接口行为无回退，新增两个列表接口符合规格。
- 用户、文档和工单存入 MySQL，应用停止再启动后仍可查询。
- 角色、权限和关联表由同一初始化脚本创建，但不提前开放 RBAC API。
- 逻辑删除过滤、唯一约束、工单事务和并发结果均有真实 MySQL 自动化测试。
- 至少两条业务查询执行 `EXPLAIN ANALYZE`，覆盖索引结论来自真实输出。
- 最终 `mvn test`、实际启动和 HTTP 流程通过；测试数量和警告写入 handoff。
- README 反映 MySQL 前置条件、配置方法、初始化方式、运行和测试步骤。

## 并行学习任务

算法练习不阻塞数据库任务，但仍属于第二周验收：完成链表、栈、队列共 5～7 题。每题记录题目、核心数据结构、时间复杂度、空间复杂度和一周后复写结果；不要把算法代码混入本项目生产包。

## 计划审阅与执行选择

本目录是实施计划，不是实施授权。用户审阅整个目录并选择执行方式后，才可修改生产代码：

- 子代理驱动（`Subagent-driven`）：每个任务由独立实现者完成并经独立审查，质量门槛最高、上下文成本较高。
- 原生执行（`Native`）：当前会话按计划逐项实现，最后进行一次整体审查，依赖连续性更好、成本较低。

本计划任务前后依赖较强，推荐原生执行（`Native`）；数据库配置、Mapper 接口和后续分页查询共享同一组类型，连续实现能减少跨代理接口漂移。
