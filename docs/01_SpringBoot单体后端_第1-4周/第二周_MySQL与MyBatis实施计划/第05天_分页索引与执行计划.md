# 第 05 天：分页、索引与执行计划实施计划

> **供执行者使用：** 实施本计划前必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，并使用复选框（`- [ ]`）逐项跟踪。

**目标：** 为文档和工单增加稳定分页与条件查询，使用真实数据和 `EXPLAIN ANALYZE` 验证联合索引及覆盖索引，不编造性能收益。

**架构：** Controller 接收查询参数，Service 使用统一 `PageRequest` 校验并计算 offset，Repository 接收持久化查询对象，Mapper XML 生成条件 SQL 和独立 count SQL。列表返回摘要 DTO，避免加载文档正文和工单描述。

**技术栈：** Java 21、Spring Boot 4.1.1、MyBatis XML 动态 SQL、MySQL 8.4 B+Tree 索引、JUnit 5、MockMvc、`EXPLAIN ANALYZE`。

**设计规格：** `docs/01_SpringBoot单体后端_第1-4周/2026-10-06_MySQL与MyBatis持久化设计.md`

## 全局约束

- 新增接口固定为 `GET /documents` 与 `GET /tickets`，不改变同路径 POST。
- 页码从 1 开始，默认 `page=1`、`size=20`，最大 `size=100`。
- 排序固定为 `created_at DESC, id DESC`；SQL 必须同时包含两个排序字段。
- 文档条件为 `titlePrefix` 前缀查询；工单条件为可选 `status` 和标题 `keyword`。
- 列表不返回 `content` 或 `description`；所有查询过滤 `deleted = 0`。
- LIMIT 和 OFFSET 使用 `#{}` 绑定，排序字段固定写在 SQL 中，不接受客户端字段名拼接。

## 审查重点

- 无筛选、空白筛选、组合筛选的 count 与 items 条件是否一致。
- `page` 和 `size` 乘算是否溢出；本计划限定 `size <= 100` 并使用 `long` 计算 offset 后检查范围。
- 无效工单状态查询参数是否返回 400 而不是 500。
- 同一 `created_at` 下是否使用 `id` 保证分页顺序稳定。
- 执行计划是否因数据量太小选择全表扫描，结论是否如实记录而非强行宣称索引生效。
