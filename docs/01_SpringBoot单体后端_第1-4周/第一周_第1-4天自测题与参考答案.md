## 第 1 天：项目骨架与用户纵向切片（2026-10-05）

### 应掌握的内容

- Spring IOC、依赖注入、Bean 和构造器注入。
- Controller、Service、Repository、DTO 和领域模型的职责。
- 接口与实现分离、泛型、`Optional`、`ConcurrentHashMap` 和 `AtomicLong`。
- 用户创建、查询、参数校验和资源不存在处理。

### 自测题与参考答案

#### 1. `本次补充` 什么是 IOC 和依赖注入？本项目如何体现？

IOC 表示对象的创建和依赖关系由 Spring 容器管理，而不是业务类自己 `new` 所有依赖。依赖注入是容器把所需对象传入组件的方式；例如 `UserController` 通过构造器接收 `UserService`，`UserService` 通过构造器接收 `UserRepository`。

#### 2. `本次补充` 为什么优先使用构造器注入？

构造器注入让依赖显式且可设为不可变，实例创建时就保证依赖齐全；测试可以直接传入替身，也避免字段注入隐藏依赖或产生未初始化状态。

#### 3. `本次补充` Controller、Service 和 Repository 分别负责什么？

Controller 处理 HTTP 路径、请求体、校验和状态码；Service 处理业务规则和用例编排；Repository 定义保存和查询数据的持久化契约。Controller 不应直接操作存储。

#### 4. `本次补充` 为什么 `UserRepository` 要定义成接口？

接口表达 Service 真正需要的能力，并隔离存储细节。第一周可以使用内存实现，第二周可以换成 MyBatis 实现，而 `UserService` 的主要业务代码不需要随之重写。

#### 5. `本次补充` DTO 和领域模型为什么不直接合并？

DTO 表示外部输入并承载 Jakarta Validation 规则；领域模型表示系统内部业务数据。分开可以避免客户端控制 ID 等内部字段，也能让 API 输入结构和领域结构独立演进。

#### 6. `本次补充` `ConcurrentHashMap` 和 `AtomicLong` 在内存 Repository 中分别解决什么问题？

`ConcurrentHashMap` 提供线程安全的键值存取；`AtomicLong.incrementAndGet()` 原子地产生不重复的递增 ID。它们适合第一周轻量练习，但不能提供数据库持久化、事务和跨进程共享。

#### 7. `本次补充` 为什么查询结果使用 `Optional<User>`，而不是直接返回 `null`？

`Optional` 明确表达“可能不存在”，迫使调用方处理缺失路径。Service 可以在一个清晰位置把空结果转换为 `ResourceNotFoundException`，减少空指针和含糊约定。

#### 8. `本次补充` 创建用户和查询用户应分别返回什么 HTTP 状态？

创建成功返回 HTTP 201；查询成功返回 HTTP 200；用户不存在返回 HTTP 404；请求字段无效返回 HTTP 400。HTTP 状态表达传输层结果，响应体中的错误码表达应用层分类。

#### 9. `本次补充` `ApiResponse<T>` 为什么使用泛型？

统一响应都包含 `code`、`message` 和 `data`，但 `data` 可能是 `User`、`Document`、`Ticket` 或其他类型。泛型让同一结构复用且保留编译期类型信息，避免使用无类型的 `Object`。

#### 10. `本次补充` 用户不存在时，为什么由 Service 抛业务异常而不是 Controller 自己判断？

“按 ID 获取用户，不存在即失败”属于用例语义，应集中在 Service。Controller 只负责把已经定义的业务结果交给统一异常处理器映射为 HTTP 响应，避免每个接口重复判断。

### 掌握标准

能够从 `POST /users` 或 `GET /users/{id}` 出发，说明 Spring 如何注入依赖、每一层做什么，以及内存 Repository 如何生成 ID 和表达“查不到”。

## 第 2 天：知识文档纵向切片（2026-10-06）

### 应掌握的内容

- 复用用户模块的分层模式完成第二个纵向切片。
- 文档创建、按 ID 查询、标题和正文校验。
- 成功路径、边界路径和资源不存在路径的测试。
- 内存存储的阶段价值与限制。

### 自测题与参考答案

#### 1. `本次补充` 什么是“纵向业务切片”？

纵向切片是围绕一个可观察用例同时贯通 Controller、Service、Repository、模型、DTO、异常和测试，而不是先把所有 Controller 或所有 Repository 一次写完。`POST /documents` 和 `GET /documents/{id}` 构成了一个小而完整的文档切片。

#### 2. `本次补充` 为什么文档模块复用用户模块的结构，而不是重新设计一套分层？

两者都具有创建、按 ID 查询、输入校验和不存在处理。复用经过验证的结构可以降低认知成本、保持一致行为，也让差异集中在文档自己的字段和规则上。

#### 3. `本次补充` 文档创建请求为什么只接收标题和正文，不接收 ID？

ID 是服务端存储层生成的资源身份，客户端不应控制。DTO 只暴露用户可以提供的字段，Repository 生成 ID 后再返回完整领域对象。

#### 4. `本次补充` 为什么标题需要非空和最大 200 字符两类校验？

非空保证标题有业务意义，最大长度建立明确边界并为后续数据库列设计做好契约。只做非空无法阻止极端长输入，只做长度也可能接受空白字符串。

#### 5. `本次补充` 文档不存在为什么可以复用用户模块的全局异常处理？

两者都属于“按 ID 查询资源但资源不存在”。`ResourceNotFoundException` 可以携带资源名称和 ID，统一处理器再稳定映射为 HTTP 404 和 `RESOURCE_NOT_FOUND`，无需为每种资源复制处理器。

#### 6. `本次补充` 文档 Service 单元测试至少应覆盖哪些行为？

应覆盖创建后获得 ID、连续创建获得不同 ID、按 ID 返回已有文档以及查询不存在文档时抛异常。这些测试验证业务契约，不依赖 HTTP 或 Spring 上下文。

#### 7. `本次补充` 文档 Controller 集成测试为什么还要重复验证创建和查询？

Service 测试不能证明 JSON 反序列化、Jakarta Validation、路由、HTTP 状态码、统一响应结构和全局异常映射正确。Controller 集成测试验证的是完整 Web 边界。

#### 8. `本次补充` 第一周使用内存 Repository 有什么优点和限制？

优点是依赖少、反馈快，适合先学习分层和完成业务闭环；限制是应用重启数据丢失、不能跨实例共享，也缺少数据库事务、约束和真实查询能力。因此它是阶段实现，不是最终持久化方案。

### 掌握标准

能够说明如何复用用户切片快速实现文档切片，并区分 Service 单元测试和 Controller 集成测试各自证明了什么。

## 第 3 天：工单状态机（2026-10-06）

### 应掌握的内容

- 枚举和状态机表达有限业务状态。
- 工单初始状态、合法流转、跳级、回退和重复设置。
- Controller、Service、Repository 在状态更新中的职责。
- JSON 枚举解析错误与业务状态流转错误的区别。

### 自测题与参考答案

#### 1. `本次补充` 为什么工单状态使用枚举，而不是任意字符串？

枚举把状态限制为 `PENDING`、`PROCESSING`、`RESOLVED` 和 `CLOSED`，提供编译期类型安全，并允许把状态流转规则集中在状态类型中。任意字符串容易产生拼写错误和无效状态。

#### 2. `本次补充` 当前合法状态顺序是什么？

`PENDING → PROCESSING → RESOLVED → CLOSED`。只允许前进到紧邻的下一个状态；跳级、回退、重复设置以及从 `CLOSED` 继续流转都应拒绝。

#### 3. `本次补充` 为什么创建工单时初始状态必须由服务端固定为 `PENDING`？

新工单尚未开始处理，业务定义决定其初始状态。若允许客户端任意指定，调用方可以绕过状态机直接创建已解决或已关闭工单。

#### 4. `本次补充` `TicketStatus.canTransitionTo` 为什么比在 Controller 中写多个 `if` 更合适？

流转规则属于状态领域知识，与 HTTP 无关。集中在状态类型后，Controller、Service 测试或未来其他入口都能复用相同规则，也避免多个接口出现不一致判断。

#### 5. `本次补充` 为什么状态校验仍由 Service 调用，而不是 Repository 判断？

Repository 负责保存和读取状态，不负责决定业务流转是否合法。Service 编排“读取当前工单—校验规则—更新”，能让持久化实现保持可替换。

#### 6. `本次补充` “无法识别的状态值”和“已识别但不允许的流转”有什么区别？

例如 `"UNKNOWN"` 无法反序列化成枚举，属于请求体格式问题，返回 `INVALID_REQUEST_BODY`；`PENDING → RESOLVED` 中两个状态都合法，但组合违反状态机，返回 `INVALID_STATUS_TRANSITION`。

#### 7. `本次补充` 为什么重复设置当前状态也应拒绝？

状态更新表示一次真实业务流转。把当前状态再次设为自身没有产生流转，却可能让调用方误以为操作成功并触发重复副作用，因此应明确返回业务错误。

#### 8. `本次补充` 工单状态机测试需要覆盖哪些失败路径？

至少覆盖跳级、回退、重复设置、关闭后继续更新以及工单不存在。成功路径要覆盖完整的逐级流转，而不是只测一步。

#### 9. `本次补充` 第一周内存 Repository 更新工单状态时为什么创建新的 `Ticket` 对象？

当前领域对象没有公开修改状态的 setter。通过 `computeIfPresent` 原子替换为新对象，可以保持对象构造后的状态稳定，并将内存映射中的更新集中完成。

#### 10. `本次补充` 第一周的内存实现是否已经解决两个并发状态更新的业务竞态？

没有完整解决。线程安全集合只保证单次集合操作安全，不能自动让“读取—校验—更新”整个业务序列原子化。这个问题在第二周通过真实数据库事务和行锁处理。

### 掌握标准

能够不看代码写出状态图，区分格式错误和业务流转错误，并解释为什么线程安全容器不等于整个业务操作具备并发安全性。

## 第 4 天：统一异常、测试与周验收（2026-10-06）

### 应掌握的内容

- `ApiResponse<T>`、HTTP 状态码、应用错误码和中文消息。
- `@RestControllerAdvice` 统一异常映射。
- TDD 的 RED—GREEN—重构循环。
- 单元测试、Controller 集成测试、完整回归和真实运行验证。

### 自测题与参考答案

#### 1. `本次补充` 为什么既需要 HTTP 状态码，也需要应用错误码？

HTTP 状态码让通用客户端快速判断成功、参数错误、未找到或冲突；应用错误码提供稳定、细粒度的业务分类，例如同为 400 的 `VALIDATION_ERROR`、`INVALID_REQUEST_BODY` 和 `INVALID_STATUS_TRANSITION`。

#### 2. `本次补充` `@RestControllerAdvice` 解决了什么问题？

它集中把异常转换为 HTTP 状态和统一响应，避免每个 Controller 重复 `try/catch`。这也保证同类错误在用户、文档和工单接口中具有一致的错误码和结构。

#### 3. `本次补充` 为什么面向用户的消息使用中文，而 URL、JSON 字段和错误码保留英文？

中文消息便于当前目标用户理解；URL、字段名和错误码属于机器可读契约，英文形式更稳定、便于代码处理和跨语言调用。展示文本与机器标识应分开。

#### 4. `本次补充` TDD 中 RED、GREEN 和重构分别表示什么？

RED 是先写测试并确认它因目标行为缺失而失败；GREEN 是只写足够的生产代码让测试通过；重构是在测试保护下改善结构而不改变行为。没有观察到有效失败的测试不能证明它真的能抓住缺陷。

#### 5. `本次补充` Service 单元测试和 MockMvc Controller 集成测试有什么区别？

Service 测试直接调用业务类，关注业务行为、执行快；MockMvc 测试通过 Spring Web 层验证路由、JSON、校验、状态码、统一响应和异常映射。二者覆盖不同风险，不能相互替代。

#### 6. `本次补充` 为什么目标测试通过后还要运行完整 `mvn test`？

局部修改可能破坏其他模块、Spring 上下文或共享异常处理。完整回归可以发现跨模块影响；第一周最终以 40 个测试全部通过作为收尾证据。

#### 7. `本次补充` 为什么测试通过后还要实际启动应用并调用 HTTP？

测试不能覆盖所有启动配置、端口、序列化和真实调用环境问题。实际启动并调用关键链路可以验证应用能够运行，而不仅是测试代码能够运行。

#### 8. `本次补充` 第一周为什么关闭 Spring Docker Compose 集成？

当时仓库中的 `compose.yaml` 为空且 Docker Engine 未运行，自动集成会阻止应用启动。第一周尚不需要数据库和缓存，所以先禁用；待配置真实服务并确认 Docker 可用后再启用，而不是保留一个无效依赖。

#### 9. `本次补充` 第一周为什么不提前加入 MySQL、Redis、Spring Cloud 或 AI 组件？

第一周目标是掌握 Java、Spring Boot、分层、REST 和测试，并交付小而完整的单体切片。提前加入后续技术会扩大排错面并掩盖基础概念，违反分阶段学习路线。

#### 10. `本次补充` 第一周达到什么条件才可以进入第二周？

用户、文档和工单三个切片可调用；参数错误和业务错误有稳定响应；Controller 不直接访问 Repository；自动化测试和真实运行验证通过；能复述一次请求的完整分层链路，并明确内存存储只是阶段实现。

### 掌握标准

能够解释统一响应和全局异常如何协作，区分不同测试层次，并用第一周的实际证据说明为什么功能不仅“写完了”，而且“被验证过”。
